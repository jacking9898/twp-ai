# YouTube 实时语音翻译适配与实测

日期：2026-10-23。环境：本机 Mac / Chrome、已有页渡开发版、现有 DeepSeek · deepseek-flash 配置、本机 Whisper ASR 与 Qwen3-TTS 原讲者参考音色。

## 实现

沿用真实音轨 → 识别英文 → 当前自定义 AI 翻译 → 本机中文配音 → 画面与中文同步的流程，不依赖 YouTube 字幕轨道。画面使用本机 WebCodecs VP8 缓冲；译文和配音使用同一份中文文本。

本轮新增：

- 在广告期间开启配音时等待正片，保留广告原声，不将广告音频送入识别或建立讲者参考。播放中插入广告时清空旧配音和捕获，正片就绪后重新连接。
- YouTube 在同一个 video 元素上替换媒体时，释放旧捕获轨道和处理节点；等新媒体可读后重新获取音轨与画面。没有沿用已经结束的捕获轨道。
- 通过 YouTube 原生推荐链接切换视频时，清理旧会话、文字和画面，恢复原声。新视频可重新开启；清理旧页面的轮询不会再关掉刚开启的新会话。
- 没有正在播放的配音时，实时输出面板显示等待提示，避免切换后保留上一支视频的识别文字。配音文字叠加层仍只显示当前播放段落。
- 增加 YouTube 专用媒体回归命令和真实 Chrome 页面内切换验收脚本。

仅操作专用测试标签。使用已有模型配置，没有导出、复制密钥或读取扩展私有设置；根据用户此前授权，短暂显示专用标签完成音频激活，随后恢复后台。没有操作日常工作标签。

## 自动检查

69 项 Node 检查、19 项 Python 检查通过，最终构建通过。覆盖原有自定义 AI 管线、捕获顺序、取消、声学参考与 YouTube 字幕辅助逻辑。

浏览器媒体回归使用真实编解码、真实音频播放和明确标注的模型夹具：

- YouTube：广告中启动、中插广告换源、同页媒体替换、页面内导航后立即重新开启、旧文字清理、单一入口、暂停恢复、拖动、关闭恢复原声与外挂字幕、视频结束后播放末段，以及超过 100 秒的历史缓冲清理。
- B 站：原同步观看长时间回归通过。
- 原语音流程：人物参考导入/捕获/取消、跨页复用、字幕时钟、自定义 AI 传输、错误及 SPA 清理通过。

运行：`PLAYWRIGHT_BROWSERS_PATH=.local-data/browsers npm run test:voice:youtube`。模型夹具不作为真实翻译或音色质量证据。

两支视频共实际开始播放 46 段中文配音。两轮的暂停保持、恢复、拖动后重新配音、关闭后移除画面和文字并恢复原声及外挂字幕均通过。这两轮最终记录没有模型忙、过旧丢弃、缓冲失败或超时提示。

原生推荐链接从感恩主题切换至机场主题，页面没有重新加载（保留同一文档标记）；旧语音停止、旧画面/叠加文字移除、设置面板旧识别文字清空、原声恢复、页渡入口仍只有一个。新视频随后重新开启并完成上述 90 秒检查。

这些是选定片段的功能和内部时钟验收。冷启动需要额外模型加载时间；没有逐句人工评分或音色盲听评分。此前美食广场补充样本曾出现模型忙及跳过旧结果的提示，说明并发负载仍可能影响连续性。


## 补充真实本机模型检查

独立无头浏览器也播放了感恩主题的真实 YouTube 音轨，产生 5 段实际配音，使用原讲者参考；首次开始播放等待约 14.11 秒，暂停、拖动与恢复检查通过。该轮使用本地离线翻译，不使用日常浏览器密钥。其译文将 `Thanksgiving Day` 误译为“万圣节”，未将它计为译文正确，也未将它混入当前 DeepSeek 的验收段数。

## 限制

同步观看通过延后画面来匹配中文配音的片段进度，识别、翻译和合成仍需时间；上述时钟测量没有独立验证中文音素和嘴形，也不代表零延迟或连续无停顿。

短分段仍可能截断英文词句，造成漏词、不完整译文或人名误识别。原讲者参考音色链路已实际运行，未完成人工盲听相似度评分。本轮验证普通公开视频；Shorts、直播、付费/受保护媒体及整支长视频未验收。
