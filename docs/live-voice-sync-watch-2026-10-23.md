# 视频实时语音翻译：同步观看验收

日期：2026-10-23。本次最终控制器版本为 9。使用英语原音轨识别 → 当前已配置的 DeepSeek · deepseek-flash 翻译 → 本机原讲者参考音色合成。没有用视频字幕代替音轨识别，也没有把日常浏览器密钥复制到测试浏览器。

## 修复内容

- 默认同步观看：原视频继续提供待识别的音轨，独立缓冲画面按当前中文配音的进度显示；配音和文字使用同一份译文。可以选择画面直接播放。
- 初始分段约 3–3.5 秒建立原声参考，随后优先在词间停顿提交，连续讲话最长约 4.5 秒。自定义 AI 模式重叠处理两段，保证识别和播放顺序，限制待处理队列，超时不积压旧内容。
- 上一版真实 Chrome 在源视频约 92.8 秒触发 `Picture history limit`：MediaRecorder 的实际关键帧间隔太长，无法安全清理旧画面。最终改为 WebCodecs VP8，每秒主动要求关键帧；按实际关键帧清理缓冲，不依赖 MediaRecorder 的可选提示。
- 自行封装单视频轨 WebM，每帧使用原视频时间和实际持续时间，防止可变帧率造成缓冲空洞。编码尺寸最多 1280×720，最多 30 fps；编码器排队最多 4 帧，待追加队列最多 8 MB / 180 块，目标历史约 24 秒，当前配音仍需的画面延后清理，极端情况下 60 秒后停止并恢复原声。画面只在内存中处理。
- 中文语音开始前等待画面定位完成，播放中以语速微调纠偏，较大偏差才跳转。暂停保持画面和语音，恢复后重新对齐；拖动和倍速变化重建缓冲；原视频结束后播放已采集的末段。正常暂停引起的播放取消不报成解码失败。
- 同步期间隐藏按原时间出现的外挂字幕，关闭后恢复；原视频烧录字幕随缓冲画面移动。关闭、错误和切换页面时释放捕获、编码器、缓冲与配音，恢复原声。

浏览器机制依据：[WebCodecs 强制关键帧与编码缩放](https://www.w3.org/TR/webcodecs/)、[MSE WebM 初始化段、媒体段和随机访问点](https://www.w3.org/TR/mse-byte-stream-format-webm/)。当前同步模式需要支持 VideoEncoder、MediaStreamTrackProcessor 和 VP8 MediaSource 的浏览器，不支持时提示使用直接播放。

## 自动检查

52 项 Node 检查、19 项 Python 检查通过；构建通过。另有两条独立无头浏览器流程通过，使用真实媒体处理和明确标注的模型夹具，不作为真实模型质量证据：

1. 原语音流程：人物参考导入/捕获/取消、跨页复用、字幕时钟、真实 PCM、自定义 AI 传输、错误和 SPA 清理。
2. 同步观看：真实 WebCodecs 编码 → WebM → MediaSource 解码，真实音频播放；主动制造画面落后并检查恢复，暂停 1.5 秒后继续播放 4 秒检查时钟，拖动重建、关闭恢复原声及外挂字幕、源视频先结束后播完末段。

新增长时间回归将测试视频延长到 120 秒，连续播放超过 100 秒后，历史起点已清理至 76.258 秒，当前画面位置约 94.831 秒，内部画面/配音映射时钟偏差约 0.00475 秒。另对最初几秒原文产生 35 秒夹具配音，源视频超过 26 秒时当前画面仍保留，没有误删配音所需的关键帧。

命令：`PLAYWRIGHT_BROWSERS_PATH=.local-data/browsers npm run test:voice`。Python 使用 `.local-data/voice/.venv` 项目本机虚拟环境执行 `unittest discover -s local-voice`；首次浏览器夹具运行需要 ffmpeg 生成测试视频。

## 质量边界

同步观看通过整体延后画面来对齐中文，翻译和合成耗时仍然存在。这是片段画面与配音进度的内部时钟测量，不是嘴形与中文音素的独立测量，也不能证明逐字口型同步。

语音识别仍会在硬分段处截断词句，中文可能不完整。例如实测将句尾 `politician` 的一部分识别为 `policy...`，随后模型按“政策……”翻译；不能把流水线播放成功等同于每句翻译正确。历史较慢版本的样本曾出现跳过过旧结果的提示；最终这三轮没有出现该提示。原讲者参考音色链路已运行，音色相似度没有完成人工盲听评分，不能声称与原声完全一致。

本报告的原始范围为 B 站；后续已完成普通 YouTube 视频适配和两支真实自定义 AI 视频抽测，见 [YouTube 实测记录](live-voice-youtube-2026-10-23.md)。整支长视频、多小时播放、画中画和受保护媒体仍未验收。
