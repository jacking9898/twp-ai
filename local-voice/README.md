# 本地视频中文配音（实验版）

Windows 后端选用 faster-whisper small.en（GPU，int8_float16）→ OPUS-MT en-zh（CPU）→ GPT-SoVITS v2Pro（GPU，FP16）。第一版支持英语转简体中文、中文字幕直接配音。无需训练；默认音色使用官方 CosyVoice 示例的 3.48 秒中文参考语音，固定来源和 SHA-256 保存在本机 `reference-source.json`，参考样本不随安装包分发。可用自己的 3–10 秒中文 WAV 和对应文字替换参考音频。

Apple Silicon Mac 的运行方法见文末对应章节。

当前版本仍是实验实现：实际视频中，逐条按字幕时长拉伸配音会出现语速忽快忽慢，同步和听感尚未达到稳定可用的程度。时间轴测试验证调度和状态恢复，不代表实际语音质量合格。人物音色复用已经提供，实际相似度取决于原声质量和模型跨语言合成能力。

## 安装与启动

Windows、Python 3.11 / 3.12、NVIDIA CUDA 显卡、ffmpeg（加入 PATH）。当前目标机器为 RTX 3050 8GB。安装期间需要网络；识别和配音模型从本机读取，默认文字翻译调用扩展中配置的自定义 AI。建议预留至少 12GB 磁盘空间（主模型及中文发音辅助权重约 2.7GB，另有 CUDA/PyTorch 和依赖）。大文件从 ModelScope 镜像下载，逐个核对固定 Hugging Face 修订的 SHA-256；小配置文件直接从固定修订获取。

在仓库根目录运行：

```powershell
./local-voice/setup.ps1
./local-voice/start.ps1
```

`start.ps1` 默认独立后台运行，等待模型加载完成并显示 `Ready` 后才可连接；关闭启动终端不会关闭服务。重复执行会检测已有服务，不重复加载模型。日志在 `.local-data/voice/server.log` 和 `server.err.log`。电脑重启后需再次启动。若终端限制独立后台进程，可在普通 PowerShell 窗口运行 `powershell -ExecutionPolicy Bypass -File ./local-voice/start.ps1 -Foreground`，保持该窗口打开，按 Ctrl+C 停止。

若希望使用自己的中文参考语音：

```powershell
./local-voice/setup.ps1 -ReferenceAudio 'C:/audio/reference.wav' -ReferenceText '这段音频里实际说出的中文。'
```

安装脚本失败后可以重跑，已下载文件会复用。源码版本和模型修订保存在 `.local-data/voice/upstream-revision.txt`、`model-revisions.json`；再次运行不更新已有源码或模型。setup 最后会实际翻译并合成 `.local-data/voice/smoke.wav`，同时载入 ASR 检查显存。完成此测试才代表模型已可运行。旧版本的 Windows 合成参考音色可用 `.local-data/voice/.venv/Scripts/python.exe local-voice/download_reference.py --upgrade-default` 升级，旧样本自动备份；自定义参考音色不会被覆盖。换参考音色后需重启服务。

重新加载扩展并刷新视频页，在 YouTube / B 站播放器页渡菜单点击「开启本地中文配音」。更多设置可测试连接、选择字幕或音频模式。配音不会自动开启。目标语言固定为简体中文。默认复用扩展自定义 AI，可在「语音翻译方式」切换本地离线翻译；两种方式都可用于音频识别模式。

### 保存并复用人物原声

在「更多设置」展开「采集原声，保存人物或系列音色」。以 1 倍速播放清晰的单人讲话，点击「采集当前视频 7 秒原声」；也可以导入 3–10 秒参考音频。采集不使用麦克风、不改变视频播放状态，暂停、拖动或点击取消会结束采集。英语原声会在本机自动识别参考文字；中文原声需填写实际说出的文字。核对文字、语言并填写人物名称后，点击「保存人物音色到本机」。

保存后选择「同一位讲者」或「当前视频系列」，点击记住音色。讲者来自当前页的 YouTube 频道 / B 站 UP 主链接；系列对应 B 站同一 BV 的分 P、YouTube URL 中的播放列表，没有播放列表时只绑定当前视频。后续视频开启配音时，会自动读取此讲者或系列的音色；也可手动选择已保存的音色。「试听中文音色」可先检查效果。

这是用原声作为合成参考，无需重新训练或下载新模型；参考英语原声也可用于中文配音。最多保存 50 个人物音色，音频和文字只存于 `.local-data/voice/profiles/`，服务重启后保留。默认参考音色仍可选择。需要更新本地服务并重新加载扩展才能使用新接口。

「实时识别配音语速」只用于没有字幕时间轴的音频识别，可选择 0.75–2 倍，并按网站记住。字幕同步模式不使用此设置，而是用实际音频长度除以该条字幕的 `end - start`，将整段配音匹配到这条字幕的起止时间；视频倍速仍由播放器控制，保持音调。字幕同步开启时此语速选项禁用。

## 播放行为

- 有可读字幕时，逐条使用 SRT/VTT 或平台字幕里的起止时间，提前合成当前位置后约 60 秒（最多缓存 64 段）。长、短配音都匹配该条字幕的完整时段。拖动、暂停恢复和播放器缓冲恢复时校准到视频位置，日常播放容忍时钟小幅抖动，避免不断跳转音频造成卡顿。模型未及时完成时保留原声、继续播放；迟到结果只从当前对应位置播放，过期字幕不补播。特别短或不准确的字幕时段仍会影响听感。
- 没有文字字幕时，读取当前视频元素的音轨，优先在语音停顿处提交 PCM 分段，连续讲话约 3 秒后优先在词间停顿提交，最长约 4.5 秒一段。识别、翻译、合成完成后顺序播放，新配音不会打断上一段。推理和播放分别最多保留两段待处理内容，持续跟不上时丢弃过期片段。可选同步观看会缓冲画面，使配音对应缓冲后的画面；直接播放模式的画面仍保持原时间，中文会滞后。
- 第一段配音就绪后静音原视频，替换整个原声（包括背景音乐）。配音队列播放完、关闭、跳转到其他视频、广告、服务失败或当前字幕配音未就绪时会恢复原声。扩展不会主动暂停或恢复视频。字幕配音跟随视频时钟，直接播放模式暂停、拖动或倍速变化时丢弃旧请求和旧音频。同步观看暂停时同时暂停画面和当前配音，保留已有缓冲；拖动或倍速变化重建缓冲。菜单会标明实际使用的是「字幕同步配音」还是「实时配音（与画面有延迟）」，自动模式找不到可读字幕时仍会使用后者。
- 受 DRM 或跨域限制的音频可能无法读取；此时停止并提示使用字幕或导入 SRT/VTT。不会申请麦克风或捕获整个桌面。
- 暂不提供多说话人自动分离、背景音乐保留、口型同步或无延迟保证。

## 本地数据与接口

模型、独立环境、参考 WAV 都在被 Git 忽略的 `.local-data/voice/`，不进入扩展安装包。服务只监听 `127.0.0.1:8765`，不接受网站 Origin；扩展通过自定义请求头和短期会话令牌访问。没有开放 CORS。推理串行执行，缓存按文字、语言和人物音色区分，只在内存中，最多约 32 MB。运行不下载模型、不记录普通配音音频、字幕或请求日志；只有点击保存人物音色时才持久保存参考语音和文字。关闭服务释放模型显存。

客户端音频来自 `HTMLMediaElement.captureStream()`，该接口的音频捕获独立于元素静音；合成音频通过独立 Web Audio 输出，避免再次识别自己的配音。参考：[W3C 媒体捕获规范](https://www.w3.org/TR/mediacapture-fromelement/)。当前用 ScriptProcessor 做分段，后续可替换为 AudioWorklet。

上游：[faster-whisper](https://github.com/SYSTRAN/faster-whisper)、[OPUS-MT en-zh](https://huggingface.co/Helsinki-NLP/opus-mt-en-zh)、[GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS)。第三方源码和模型按各自许可获取，不随扩展包分发。

## Apple Silicon Mac

M 系列 Mac 默认使用：MLX Whisper small.en 本地识别 → 扩展已配置的自定义 AI 翻译 → Qwen3-TTS 0.6B Base 8bit 本地原声音色参考合成。无需 CUDA，不运行 Windows 安装脚本。首次安装需 Python 3.11 和网络；默认只安装识别和配音模型。可选离线翻译增加约 2.5 GB 权重，全部模型共约 6 GB；实际速度以本机播放测试为准。

```sh
./local-voice/setup.sh
./local-voice/start.sh
```

默认自定义模式需要先在扩展 AI 设置中保存服务并选为当前模型。视频设置可选择具体模型，或跟随当前自定义模型；只发送识别文字、前文语境及视频标题，原声音轨和人物参考不上传，密钥仅保留在扩展后台。翻译失败直接显示错误，不自动改用离线模型。译文与配音使用同一份中文文字。

如需完全离线翻译，运行 `./local-voice/setup.sh --offline-translation` 安装可选 Qwen3 4B Instruct 4bit，再在视频设置中选择「本地离线翻译」。已有离线权重保留，不会被删除；仅离线请求时加载，不随语音服务预热。

服务仍只监听 `127.0.0.1:8765`，启动时预热识别和配音，显示 Ready 后连接。后台启动采用 macOS 独立会话，日志仍在 `.local-data/voice/`；`./local-voice/start.sh --foreground` 可前台运行。模型下载时记录精确修订，已有文件可续传；运行时设置离线模式。旧 Windows/CUDA 后端继续保留。

### 按需自动启动与模型页面

Mac Chrome 已安装本地模型后，双击 `local-voice/安装本地连接.command`，完成一次性连接注册。安装器只从 Chrome 的扩展配置中查找本项目的开发版扩展 ID，不读取登录信息；已加载扩展时 `setup.sh` 会尝试自动完成此步骤。安装不需要开机启动项或管理员权限。项目移动或更换扩展 ID 后需重新注册；已有其他安装位置的同名组件时会提示处理，不覆盖它。

重新加载扩展并刷新视频页，点击「模型服务与实时输出」，或从扩展设置进入「本地语音模型」。默认开启「开启语音翻译时自动启动」：在视频页开启配音，如果服务未运行，扩展通过本机连接组件启动并等待模型就绪；电脑重启后仍可按需启动，无需重复运行脚本。关闭开关后，仅连接已运行的服务，未运行时提示手动启动。

模型页面提供启动、停止并释放内存、重新检测、自定义 AI 文字测试，以及配音/识别加载阶段。停止服务会关闭正在进行的扩展配音并恢复原声；仅停止本项目记录且已核对运行路径的模型进程。默认开启「关闭语音翻译后自动释放内存」：最后一个视频关闭配音（或关闭/离开该标签页）时停止服务；暂停和拖动不触发。关闭此开关后可复用已加载的模型。悬浮控制面板顶部和视频菜单中均有显眼的模型服务入口，控制面板及模型服务页面可修改此开关。

页面实时显示识别原文、中文译文、实际正在播放的配音文字和处理耗时。运行记录最多 80 条，使用扩展的会话存储，浏览器重启后清除，可手动清空；没有将这些文本写入模型日志或永久设置。状态检测使用独立接口，不创建或挤占视频连接令牌。

本机连接组件当前支持 macOS Chrome；Windows/Firefox 的自动拉起尚未适配，仍可连接手动启动的服务。首次安装本机程序无法由浏览器扩展自行替代，机制参考 [Chrome Native Messaging 官方文档](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)。

### 实时语音翻译改进

默认选择「实时语音翻译 · 读取视频音轨」，不读取字幕轨道。约 3 秒后优先等待词间停顿提交，最多采集约 4.5 秒，较长的语音停顿可更早提交；本地识别保留同一音频会话最近的原文语境。原声采集、识别、翻译、合成仍存在不可避免的处理延迟；不会承诺与口型完全同步。

首段原声优先在约 3–3.5 秒提交以建立音色参考，后续片段再使用较完整的停顿分段。界面中的内容延迟从原片段开始位置计算，包含采集、推理和排队时间。

默认「跟随当前原讲者」使用当前会话中已识别的至少 3 秒原声建立参考，不再套用固定中文示例音色。需清晰单人讲话；多人、配乐或噪声会降低相似度。不自动创建永久人物档案，参考只在本机内存短期保存，合成所需临时 WAV 用后删除；最多保留 16 个会话，5 分钟未使用后清理。直接播放模式暂停、跳转、缓冲、广告或视频切换会清除旧音频与画面译文；同步观看的暂停保留当前匹配的画面和配音，拖动和视频切换仍清除。需要稳定跨视频音色时，仍可手动保存人物音色。

实时识别源文和译文显示在设置面板，视频内译文随实际配音播放和结束，而非抢先显示刚识别的下一段。配音播放完且队列为空时恢复原声。过期超过 12 秒的待处理内容丢弃，最多保留两段待推理和两段待播放内容，避免无限积累延迟。播放速度保留音调；默认自然语速，根据段落时长和积压最多自动提升到 1.35 倍，手动选择仍可覆盖。模型短暂忙碌时继续当前会话，不直接退出。

### 真实浏览器验证

`tests/video-dubbing-live.cjs` 是显式开启的线上测试，加载真实扩展、真实视频页面、真实 `captureStream` 和真实本机模型，不伪造识别或合成结果。它启动独立无头 Chromium，使用独立测试资料目录，不读取日常浏览器资料，浏览器输出静音。测试会访问指定网站并可能遇到网站自身的登录或播放限制，不绕过这些限制。

```sh
PLAYWRIGHT_BROWSERS_PATH=.local-data/browsers npx playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=.local-data/browsers \
YEDU_LIVE_VIDEO='https://www.bilibili.com/video/BV1TkpG6kEds/' \
YEDU_TEST_LOCAL_TRANSLATION=1 node tests/video-dubbing-live.cjs
```

独立测试资料目录不继承日常浏览器的自定义模型配置。上例显式测试可选离线翻译，不代表自定义 AI 质量验收；不会复制日常浏览器的密钥。

测试观察记录、截图和首段实际合成音频仅保存在 `.local-data/voice/evaluation/`。自动断言验证链路和恢复行为，翻译准确度、音色相似度仍需检查真实输出；接口测试通过不能替代听感验收。

参考：[MLX Whisper](https://github.com/ml-explore/mlx-examples/tree/main/whisper)、[MLX Audio 原声参考合成](https://github.com/Blaizzy/mlx-audio/blob/main/docs/guides/voice-cloning.md)。

已有自定义 AI 的后台真实 Chrome 抽测可显式运行 `YEDU_TEST_EXISTING_CHROME=1 node tests/video-dubbing-chrome.cjs`。此测试通过公开 B 站播放器控件使用当前配置，不读取密钥，结束后关闭专用测试窗口。质量和限制见 [自定义 AI 真实视频测试记录](../docs/live-voice-custom-ai-2026-10-23.md)。

### 同步观看与处理等待

实时音轨模式新增「观看方式」：默认「画面与中文同步」，也可选择「画面直接播放」。前者先缓冲中文，再显示与该段配音对应的画面；原音轨继续在后台供识别使用，不靠暂停原视频等待模型。初次仍需等待，并非零延迟或逐字口型同步。暂停、恢复会控制当前缓冲画面与配音；拖动后重新建立缓冲；原视频结束后继续播完已采集的末段。关闭或失败时移除缓冲画面并恢复原声。观看方式按网站记住。

缓冲使用本机 WebCodecs 与 MediaSource，只保留短期内存内容，不上传画面或保存视频文件。每秒主动生成关键帧，编码不超过 720p / 30 fps。限制编码队列到 8 MB / 180 帧，目标保留约 24 秒播放历史；按实际 WebM 关键帧清理，避免误删待播放画面，最长保留 60 秒后停止同步并恢复原声。暂停和加载等待不编码，恢复后继续使用原视频时间轴。源视频中烧录的内容随画面一起缓冲；网站按原时间显示的外挂字幕在同步期间隐藏，关闭后恢复。浏览器不支持或无法捕获时提示切换直接播放。尚未验收画中画和受保护媒体。

YouTube 广告期间不采集或配音，保留原声；正片就绪后重新连接捕获。广告或画质切换造成同页媒体换源时释放旧音轨并重新获取。通过推荐链接切换视频会结束旧会话和旧文字，可在新视频上重新开启。普通 YouTube 视频的真实测试记录见 [YouTube 适配验收](../docs/live-voice-youtube-2026-10-23.md)。


自定义 AI 模式最多重叠处理两段，识别保持源顺序，结果即使乱序返回也按原顺序配音。当前段等待翻译或合成时，可以先处理下一段；本地模型推理仍由服务串行保护，不同时运行两次 GPU 推理。最长采集从 6 秒缩到约 4.5 秒，不能据此保证所有视频的总等待都下降。

新模式的验证边界见 [同步观看测试记录](../docs/live-voice-sync-watch-2026-10-23.md)。
